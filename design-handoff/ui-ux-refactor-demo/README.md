# Resume 侧边栏 UI/UX 优化 Demo

## 预览

从项目根目录启动一个本机静态服务器：

```sh
python3 -m http.server 8000
```

浏览器打开 `http://127.0.0.1:8000/design-handoff/ui-ux-refactor-demo/`。建议先用 720×900 看完整编辑页，再把窗口缩到 390×844、320×844 看窄栏布局。

也可以直接打开状态：

- `?screen=directions`：简历方向室
- `?dialog=create`：新建方向
- `?dialog=delete`：删除确认
- `?state=overflow`：超页暂停打印

## 设计说明

- **任务**：在 Chrome 侧边栏里维护多份独立简历方向、直接编辑 A4 纸面并打印 PDF。
- **方向**：沿用已定稿的 A「纸面工坊」。灰卡纸工作区、白纸主角、墨蓝交互色和 A4 纸面保持一致。
- **优化重点**：在编辑页给方向室增加可见入口，同时保留 `⌘F`；缩窄到 540px 时把缩放控件放到第二行；方向卡不再重复显示“简历方向”这类泛标签，名称、最近编辑时间、当前项标识、A4 缩略图和改名/删除操作仍完整保留。
- **关键状态**：纸面编辑与缩放、正文范围线开关、方向搜索、创建与复制、改名、删除确认、联系项添加、排序入口、导入 JSON、空搜索结果、超页拦截和打印。
- **设备**：Chrome 侧边栏宽度按 320–800px 处理；预览按 720×900 与 390×844 检查。A4、9mm 边距、字体和排版算法沿用项目已确认规则。
- **动效**：编辑页与方向室切换 150ms；方向卡进入 180ms；纸面缩放 160ms；均在减少动态效果设置下关闭。
- **减法**：只删掉重复的泛标签，没有删方向名称、时间、当前状态或主动作。

## Demo 范围

这是独立设计原型，没有修改 `extension/`、`SPEC.md` 或正式产品行为。界面文案和简历内容均为虚构数据。方向、改名和编辑状态只保存在当前页面内存；刷新会重置。JSON 导入只做结构展示校验，没有复用正式版的完整领域校验，也没有模拟持久化文件句柄。PDF 按钮调用当前浏览器的打印窗口，打印结果不代表正式扩展验收。

## 评审与截图证据

- 第一轮评审为 8/10，指出方向卡片被可用高度挤短，预览和卡片边界不清。修正为宽屏完整展示 A4 缩略页，窄屏改成左侧信息、右侧整页缩略图的列表卡片。
- 第二轮评审为 9/10：宽屏卡片底边对齐，窄屏缩略图完整，方向名和当前状态仍清楚；没有新的明确问题。编辑页范围虚线本轮未改，继续作为较弱的纸面边界提示。
- [最终截图与检查报告](shots/delivery/)：包含 720×900 和 390×844 两种尺寸、遮字对比图、2 倍细节图及 `report.json`。截图检查未发现控制台错误、横向溢出、图片加载失败或可读性提示。
- 动效检查确认页面入场有反馈；录屏环境未安装 ffmpeg，因此只保留首、中、尾三帧，帧一致性检查通过。实际操作截图在 [创建、搜索、改名、删除流程](shots/interaction-flow/)。
