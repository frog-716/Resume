## Gemini 给出的唯一首选

Gemini 推荐“先选字号，再用同一个松紧旋钮调空隙”的两步办法，而不是继续把七个间距都固定乘一个系数：

1. 短稿如果用正文 10.50pt、自然间距（`τ=0.35`）就能放下，就停在这里，不为了贴近纸底继续拉开空隙。
2. 否则沿着字号和基础间距一起收紧的路线，用真实浏览器高度找最大可用字号；字号不能低于 8.50pt。
3. 固定字号后，再用一个共同的 `τ` 同时放松各间距，尽量减少底部剩余白纸；如果仍不够，则检查提高字号 0.01pt、同时收紧间距是否能得到更好的结果。
4. 最小字号和最紧间距仍超页时，全文保留并暂停 PDF 导出。

Gemini 把 `τ` 解释为：`0` 最紧、`0.35` 自然标准、`1` 最松。它提出的候选公式如下，均为**建议值**：

| 位置 | Gemini 候选公式 |
|---|---|
| 正文每行高度 | `s × (1.32 + 0.16τ)` |
| 三栏换行每行高度 | `(s + 0.50) × (1.30 + 0.14τ)` |
| 同组相邻要点 | `s × (0.12 + 0.12τ) pt` |
| 三栏条目到本段第一条要点（新增候选） | `s × (0.18 + 0.14τ) pt` |
| 大标题到第一条要点 | `s × (0.34 + 0.20τ) pt` |
| 大标题到第一组三栏条目 | `s × (0.36 + 0.20τ) pt` |
| 上段末要点到下一段三栏条目 | `s × (0.42 + 0.28τ) pt` |
| 上一块末行到下一个大标题 | `s × (0.68 + 0.42τ) pt` |

在 `s=10.50pt、τ=0.35` 时，对应数值约为：正文行高 14.45pt、三栏行高 14.84pt、要点间 1.70pt、新增间隙 2.40pt、大标题到要点 4.31pt、大标题到三栏 4.52pt、经历之间 5.44pt、板块之间 8.68pt。

## 独立复核：哪些有用，哪些不能照抄

### 有用的发现

- 现有第 1、2 条公式确实会倒挂：`1.375s = 1.30(s+0.50)` 在 `s≈8.67pt` 相等；更大字号时，字号更大的三栏标题行盒反而更矮。现有 8.50pt 时两者几乎一样高（11.69pt 对 11.70pt）。
- 原来七个候选值中，“上段要点到下一段三栏”小于“大标题到三栏”，会让经历段与段之间的界线偏弱。Gemini 提醒应分别定义这些位置，并检查它们之间的视觉层级。
- 固定字号和固定换行之后，若各行高和间隔都按同一个 `τ` 线性变化，那么总高度可以用浏览器实测的两端高度做插值；这样比凭字符数猜总高度可靠。
- Gemini 发现第七项列表没有明说“三栏条目到它自己的第一条要点”。这是值得核对的空隙，但不代表当前纸面一定完全没有空隙：第十四版演示给 `.entry-head` 留有 4px 下内边距。需要确认这 4px 是作为固定间隔保留，还是正式纳入第八条公式。

### 不能直接采纳的部分

- **与已确认规则冲突：** Gemini 把“联系方式到第一个大标题”也放进可变的板块间距公式。项目规格 L-17 已确认这段距离固定为 18.5px，不能随 `τ` 变化，应从自动间距算法中排除。
- **固定头部高度没有按本项目的实际状态测量：** 它报告 34.83pt 的“单行联系方式”头部高度，但联系方式可有一行或两行，且联系方式到首标题距离已有独立的 18.5px 规则。这个数不能直接用来算本项目页面高度。
- **系数和阈值是审美候选，不是标准答案：** `τ=0.35`、各行距上下限、底部 1.5pt 安全垫、6pt/7.5pt 余白判定，都不是 W3C/MDN 能推导出的简历最佳值。
- **没有真的跑 27 份排版或导出 PDF：** Gemini 给的是测试清单和预期，不是 27 个实测结果；混合字体额外增加 0.3–1.0px 等数字也没有在本机 Mac/真实 PDF 中验证。必须把“规范事实”和“待实测估计”分开。
- **结构适用位置需再对照演示：** 第 6 条是否覆盖教育背景、第 8 条是否用于工作/项目/教育，都要按实际模块结构逐一确认，不能只看公式名称。

## 公开资料能证明什么

- [W3C CSS Values and Units Level 3](https://www.w3.org/TR/css-values-3/)：CSS 绝对单位换算，例如 `1pt = 4/3 CSS px`。
- [W3C CSS Inline Layout Level 3](https://www.w3.org/TR/css-inline-3/) 和 [MDN `line-height`](https://developer.mozilla.org/en-US/docs/Web/CSS/line-height)：行盒会受字号、行高和字体度量影响；支持用实际排版测量，不支持某个特定简历系数就是“最好看”。
- [W3C 中文排版需求（CLREQ）](https://www.w3.org/TR/clreq/)：描述汉字排版与基线等需求；不能单独决定本简历的行距系数。
- [MDN Margin Collapsing](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_box_model/Margins_collapsing)：块元素外边距可能折叠；实现中统一使用单向间距或容器 `gap` 可减少重复/漏算，但这是工程做法，不是审美结论。
