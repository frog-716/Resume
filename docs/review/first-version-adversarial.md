# 首版无上下文对抗性审查

日期：2026-10-10。状态：建议待逐项确认，不是实现验收或已批准规格。

按用户要求启动全新 subagent，`fork_turns=none`，只给它独立审查任务和 `SPEC.md`。它被要求仅阅读该文件，不读前序对话、其他文档、源码或私人原稿，不访问网络、不修改文件。以下建议已回收到规格的待确认区，正式功能规则只维护在 `SPEC.md`。

## 1. 单页容量与最低字号

涉及L-01/L-05/L-06/D-07。再增加内容后，一页A4、所有正文完整、最低可读字号三者不能无限同时满足，必须明确容量满时的行为。

建议区分用户设置的字号和缩页后的实际字号；每次重新计算，删除内容后恢复但不超过设置值。建议正文、技能、条目、日期8.5–12pt，联系方式8.5–11pt，姓名16–24pt，分区标题10–14pt。姓名步长1pt，其他0.5pt；正文、条目、日期和联系方式自动缩小下限8.5pt，姓名和分区标题首版不自动缩小。到下限仍超页时保留全文并暂停PDF导出，由用户删减。原稿已有的小数读数首次导入保持不变，不能偷偷取整。以上是针对原稿的产品建议，不是行业强制标准。

须问用户：下限处停止缩小并暂停导出，还是继续缩到能放进一页。

## 2. PDF必须与正式纸面一致

涉及L-02/L-04/S-04。字体替换可能改变换行，保存未完成可能导出旧稿。建议编辑与导出共用固定字体和排版，等待中文输入、字体和最新保存完成后冻结同一内容；失败明确报告，不把旧PDF当新结果。工具栏和提示不打印。该建议需要成为正式约束并验证，不是已实现证据。

## 3. 换行与粘贴

涉及D-05/D-06/E-02/E-03。建议要点Enter新增下一条，Shift+Enter同条换行；姓名、日期和条目头保持单行，Enter结束编辑，粘贴换行转空格而不丢字。保留受支持的基础格式，其他样式清除。

须问用户：粘贴多段文字到要点时，自动拆成多条还是保留同条内换行。

## 4. 保存版本与PDF解耦

涉及S-01至S-05。若命名版本必须同时生成合格PDF，超页稿会连保存版本都失败。建议版本冻结内容和版面、PDF按需生成；当前稿自动保存，⌘S立即保存；恢复前默认保留现稿。建议首版有完整本机备份恢复；重复打开App尽量复用已有编辑窗口。

须问用户：命名版本只冻结内容/版面还是每次同时冻结PDF。这与来源Career-Next的版本PDF语义不同，不能直接照搬或擅自改。

## 5. 格式与快捷键的作用范围

涉及E-01/L-07与快捷键表。建议基础格式作用于选中文字或后续输入；对齐作用于当前字段；字号作用于本简历的元素类别，不做逐字字号。⌘←/→保持原生光标行为，⌘A在当前字段内全选。文字、身份、格式、增删排序和版面共用本稿撤销记录，切换简历不串稿；保存动作不进撤销栈。

作为一组交互规则核对，不必把每个实现细节变成独立问题。

## 6. 收紧首版范围

涉及D-06/E-01/S-06。建议固定四类分区和当前顺序，允许改标题及增删/排序条目和要点，空区不打印。首版不做任意字体、逐字字号、删除线、查找替换、自由画布和模板市场。简历/版本删除先考虑可恢复归档，永久删除后置。

须问用户：固定四类分区与顺序，还是首版必须支持整区增删排序。

## 审查员建议的最小首版

原稿导入核对、简历列表和复制、纸面编辑、基础格式和换行、有限字号调整、一页容量提示、可靠保存和命名快照、准确PDF、本机完整备份恢复。先验证改得动、关了不丢、导出一致。

用户要求在对话中一一核对。2026-10-11已选择第1项的方案A：自动缩字最低8.5pt，仍超页时保留全文并暂停PDF导出。手动字号范围、步长和其他意见继续核对，不视为已经采纳。全部问题对齐后，须在开发前最后一次对话给出明确启动信号；目前未开始App实现。
