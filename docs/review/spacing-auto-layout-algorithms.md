# A4 单页简历自动排版：三种重构方案

> **审查建议稿，不是产品规则。** 以下三套算法及文末推荐仅供讨论，均未获用户批准；不能据此改写 `SPEC.md`、Demo 或正式产品。本文只新增这一方案稿。

> **2026-10-14 自我对抗复核：** 原推荐方案二“先用最窄间距找最大字号，再补空间”有明显偏置：长简历通常会把可用高度几乎耗尽，导致长期停在最小间距附近。本文已撤回这条单向顺序作为推荐，并将方案二改为“字号与间距联合候选搜索”。

> **2026-10-14 业务一致性复核：** 用户已明确表达字号、行距等应随内容自动适配，并尽量利用自己设定的范围。修订稿现在把页面利用率纳入目标；“用满”的力度和可接受的底部剩余白纸仍需用户按纸面观感确认。

## 先把已确认条件和未决定事项分开

### 已确认的业务条件

- 单页 A4 纸 210×297mm，四边固定 9mm，可排区域为 192×279mm；自动排版不得改边距。[`SPEC.md` L-01/L-12](../../SPEC.md)
- 正文/技能字号在 8.50–10.50pt 之间按 0.01pt 精度自动选择；条目标题和日期始终为正文 +0.50pt。姓名 18pt、联系方式 8.5pt、分区标题 12pt 固定。[`SPEC.md` L-06/L-09/L-11/L-15](../../SPEC.md)
- 固定四个板块和顺序；工作/项目条目可以排序。条目头保持已确认的栏位比例和换行规则。[`SPEC.md` L-18](../../SPEC.md)
- 任何用户文字都必须保留。最小字号和最窄间距仍溢出时，保留原稿、提示删减、暂停 PDF 导出；当前稿与快照仍可保存。[`SPEC.md` L-08](../../SPEC.md)
- 联系区字号固定为 8.5pt、只保留指定的两行且组内不换行。联系方式放不下时提示修改并暂停 PDF，不缩字、不截断、不偷偷换行。[`SPEC.md` L-13](../../SPEC.md)
- 编辑器与 PDF 必须看起来一致，文字仍可选中/复制、链接可点击。[`SPEC.md` L-04](../../SPEC.md)

上述是产品约束，不表示下文任一算法已成为规则。编辑实时适配是本轮提出的产品背景要求；触发时机、允许的重排变化和动效尚未定义。

### 仍待确认的产品选择

- 四种间距的上下限尚未冻结。Demo 的行距 1.25–1.50 倍、三栏换行间距 1.20–1.40 倍、要点间距 0.75–2.25pt、分区前间距 5–10pt 都只是候选。[`SPEC.md` L-07](../../SPEC.md)
- “尽量用好纸面”如何定义、字号和留白谁先让步、底部空白是否可以明显大于其他空隙，仍待确认。[`SPEC.md` L-05/L-19](../../SPEC.md)
- 用户另已表达排版参数要随内容自动适配，并“尽量铺满整个我设定的范围”。这是应纳入算法的方向性业务目标；它没有给出“页面底部最多留多少白纸”、是否必须接近 0mm、或与字号/层级舒适度冲突时如何让步。不能把它扩写成“每份简历必须顶到页面底边”。
- Demo 让四类空隙共用一个进度值，并随字号轻微缩放点数间距。这只是当前候选做法，不是确认规则。[`SPEC.md` L-19](../../SPEC.md)
- `spacing-v5.md` 建议字号改变时保持版面骨架大体不变；它同样是待选建议，不是已确认规则。[第五轮间距审查](spacing-v5.md)

## 第一性原理：这不是“把总高度填满”一个目标

自动排版至少在同时拉扯六件事：

1. **可读性**：尽可能保住较大正文；在已有范围内不能把 8.50pt 下限解释成“达到后就一定舒适”。
2. **层级稳定**：正文、条目头、日期和固定标题之间应维持清楚关系，不能因内容变多而让间距挤坏层级。
3. **紧凑、范围利用与留白**：内容要有呼吸感，也要尽量利用用户设定的字号与间距范围；但填满 279mm 并不自动等于更好看。底部剩余白纸是需要纳入考虑的版面结果，不等于固定的9mm下边距。
4. **视觉平衡**：要点之间、分区之间、正文行间承担不同作用，数值同样变化不等于看起来同样变化。
5. **稳定与响应**：每次键入都重排时，版面不能在临界点反复跳动；计算也要足够快，编辑器和 PDF 要使用同一套结果。
6. **完整与可交代**：不可通过改写、删字、缩联系方式、改栏宽、强制增加页数来假装“适配成功”。

所以先定义硬约束，再选软目标。对一份稿件和一组版式参数，实际渲染器给出的内容高度记作 `H(s, g)`：`s` 是正文字号，`g=(g行距,g三栏,g要点,g分区)` 是四类间距。硬条件是所有内容都在 192×279mm 区域内、联系方式独立通过固定两行宽度检查、文字完整。软目标才是正文较大、层级顺眼、空隙舒服、视觉平衡。排版高度不能只按字符数推算：CSS 的行框高度受字体度量和 `line-height` 共同影响；换行后的行框数也决定总高度。[W3C CSS 2.2 行高计算](https://www.w3.org/TR/CSS22/visudet.html#leading)；[W3C CSS Inline Layout 字体上升/下降度量](https://www.w3.org/TR/css-inline-3/#ascent-and-descent-metrics)

**关键实现前提**：试算必须调用与编辑器、PDF 同源的排版结果，至少读取相同字体、栏宽、换行、行框和块间距。仅用“字符数 × 字号”估高无法可靠捕捉换行台阶；W3C 的分页模型也将页面视为有限宽高的矩形版面，并把排版和页面分割作为实际布局问题。[W3C CSS Paged Media 页面模型](https://www.w3.org/TR/css-page-3/#intro)

## 当前共同进度法的对抗性检查

共同进度 `t` 把四类间距映射到同一个 0–100 值，隐含了“每类间距从下限走到上限具有相同的视觉进度和代价”。这没有被业务约束或排版来源证明。

- **边际高度不一样**：行距每增加一点，会乘到许多正文行；要点间距只在要点之间出现；分区间距次数很少。相同百分比的增加可能分别多出几十毫米、几毫米或几乎看不见。实际代价还取决于这份简历的行数和项目数。
- **视觉作用不一样**：行距塑造连续阅读节奏，要点间距分隔同一层级，分区间距表达板块边界。所有空隙一起扩张，可能弱化“同组/异组”的对比。
- **字号缩小可能过早**：若规则先把所有间距压到下限再缩字，可能为了少量高度差直接损失正文清晰度，即使某类空隙还有可接受的压缩空间。反向也成立：先保字号再把所有空隙压到底，可能产生拥挤。要由明确的优先级决定，不能假装两者没有冲突。
- **只追总高会松散**：为了让 `H` 接近 279mm 而增加空隙，会把内容推向下边缘；全页高度利用率高，却可能让内容像被拉散，且末端几乎没有留白。W3C 的 `space-between` 等分布方式确实会把多余空间均匀塞到项目之间，但规范只定义对齐行为，不声称它是简历的审美最优解。[W3C Box Alignment 分布对齐](https://www.w3.org/TR/css-align-3/#distribution-values)
- **渐进值不代表渐进视觉**：浏览器换行是阈值事件。字号只改 0.01pt，某个词或中文字符就可能挪到下一行，整段高度突然跳一行；布局变量连续变化，视觉结果却有台阶。因此在临界点附近可能出现抖动或游移。
- **字号对空间的作用不该被预设为线性**：点数间距再乘字号比例，会让字号和间距一起放大；结果可能重复奖励“大字号+松间距”，也可能让小字号稿件整体过紧。若“视觉上维持同一骨架”是目标，应独立验证，不由公式推定。[第五轮间距审查](spacing-v5.md)

TeX 的 Knuth–Plass 工作提供了有用的方法论参照：它显式定义候选排版的代价，并在多个可行方案间比较整体代价，而不是认为一次局部填充自然就是最优；原论文也强调代价公式含有设计选择。[Knuth 与 Plass 原论文](https://gwern.net/doc/design/typography/tex/1981-knuth.pdf)；[Knuth TeX 源码](https://www-cs-faculty.stanford.edu/~knuth/programs/tex.web)。这只能支持“把目标和代价说清楚、比较候选”的方法，不能把 TeX 的公式照搬成简历规则。

## 三套可行算法

三套均使用已确认的边界和“文字不丢、最小值失败就暂停导出”规则。它们的间距数值仍须用用户确认后的上下限替换。

### 方案一：少量固定版式快照，选最舒适且能容纳的那一档

预先定义少量离散版式，例如“紧凑、标准、舒展”，每一档给四种间距一组具体值；这些档位不是共同百分比，数值由设计比较和用户确认得到。对每档从 10.50pt 向下寻找能完整容纳的最大字号，然后按预定排序选择字号较大、档位更舒适的一档。若档位均无法在 8.50pt 容纳，按 L-08 失败。

```text
候选 = [紧凑, 标准, 舒展]  # 每档是独立的四种间距组合
可行 = []
for 档 in 候选:
    s = 10.50
    while s >= 8.50:
        if 真实布局(s, 档) <= 279mm 且 联系区通过固定宽度检查:
            可行.append((档, s))
            break
        s -= 0.01pt
若可行为空: 保留稿件并暂停 PDF
否则选 max(可行, 按预先确认的“字号优先/舒适度优先”排序)
```

**优点**：行为可预测，容易解释和比较；只有几个候选档位，实时试算很快，调参不容易追着临界值乱跳。字号的搜索离散但有界，最多 201 次每档布局。

**缺点**：档位之间会跳变，选择点的审美判断要先由人定；特定简历可能刚好适合两个档位之间的空间组合，快照法无法精细利用。

**可解释性**：高。可以说“标准留白下，这份稿件可用 9.42pt；舒展留白只能容纳 8.96pt，所以选标准”。

**性能和抖动风险**：低到中。档位少、结果容易缓存；字号仍可能在行数变化临界处来回 0.01pt，但可用稳定排序、保留上次选中的档位，以及短暂编辑缓冲降低视觉跳动。缓冲时长/是否保留旧版面是待确认设计。

**极端内容**：短稿停在“标准”或约定的默认档，不为填满页面自动加空隙；长稿依次试较紧凑的档，字号到 8.50pt 仍放不下即暂停 PDF，完整保留内容。很长单条导致栏内多行时尊重现有换行规则，不通过改结构规避。

### 方案二：联合搜索字号与间距，按简单代价选折中点（修正版）

这一版不把间距下限当作“求最大字号”的永久起点，也不假定字号必须先于间距。每种间距在待确认范围里先设三个代表档：紧凑、舒适目标、舒展；四类间距各自取档，形成 3⁴=81 组候选。对每组间距，用真实排版结果找其最大可行字号，再按一个简单、明确的折中规则比较候选。这样长稿可以用略小一点的字号换回更舒服的行距/要点分隔，而不是自动被推向四种间距的最小值。

这里的三个代表档、舒适目标和代价权重都需要用户确认；它们不是当前 Demo 范围的自动批准。每个可行候选按“缩小字号的代价 + 间距偏离舒适目标的代价”一起打分，避免把字号或间距单方面设成绝对第一。平分时优先较大字号，再用固定顺序打破平局。代价权重本身就是产品偏好，仍待确认。

```text
profiles = 四种间距分别取 [紧凑, 舒适目标, 舒展] 的全部组合（最多 81 组）
可行 = []
for g in profiles:
    用真实布局在字号整数 [850, 1050]（单位：0.01pt）内找最大可行 s
    # 二分查找依赖“字号变大不会使总高变小”的单调假设；实现须先验证。
    if 找到 s 且联系方式独立通过固定两行宽度检查:
        记录 (s, g, 剩余白纸, 字号损失, 与舒适目标的偏差)
若可行为空: 保留全文并暂停 PDF
否则计算每个候选的总代价 J，选择总分最低者
若总分相同，优先较大字号，再按固定候选顺序打破平局
用简单文字说明具体取舍，例如“正文小了 0.1pt，换回标准行距和要点间距”
```

可把总代价写成简单的归一化分数：`J = ws×((10.50−s)/2.00)² + Σ wi×((gi−g*i)/di)² + wf×B(R)`。`g*i` 是每类间距的舒适目标；`di` 按偏离方向取该目标到相应边界的距离（向上偏用 `gmax−g*`，向下偏用 `g*−gmin`，恰好等于目标时该项为 0）；`wi` 是该间距相对其他间距的重要程度。`R=279mm−H(s,g)` 是内容结束后的剩余白纸，`wf` 表示页面利用率的重要程度。若目标是尽量铺满，`B(R)=(R/279mm)²`；若目标是留舒适区间 `[R低,R高]`，则区间内 `B(R)=0`，超出时按到区间的距离平方计。`ws`、`wi`、`wf` 及目标值都待确认。方案二只在 81 个间距档组合中优化“字号、舒适间距、页面利用率”的有限折中，不把编辑中的布局变化也混进总分；方案三则允许更完整的多目标评分。

**优点**：不会因搜索顺序把长稿固定压在最窄间距；行距、要点、分区留白各自独立，不共用同一百分比。以舒适目标为基准，短稿可以保留有呼吸感的间距，中长稿则能显式用一部分字号换取更好的层级和阅读节奏。

**缺点**：折中结果取决于舒适目标、页面利用率目标和权重，以及“字号、间距、剩余白纸谁更值得让步”；这些值无法由技术来源替用户决定。若铺满权重太高，短稿可能被撑得松散；若舒适区设得过大，短稿又可能留下用户不想要的空白。三个档位之间仍有离散跳变，可能错过中间更顺眼的版式。

**可解释性**：中。系统可以说明“正文小了 0.1pt，换回标准行距和要点间距”。如果结果只能通过复杂权重解释，或权重微调便使结果明显改变，则应改用方案一的少量人工选定档位。

**性能和抖动风险**：中。81 组各自做最多约 8 次布局测量的二分查找，粗估不超过约 650 次测量；布局可缓存。这个次数只是假设二分单调并且渲染测量轻量，实时编辑是否足够快仍需在真实版式上测量。对输入过程可做短暂缓冲，但导出前必须同步完成最终布局，编辑器和 PDF 使用同一结果。候选得分相近时，确定性平局规则可避免无意义切换；若加迟滞门槛则又多一项待确认设置。

**短、中、长内容表现**：短简历通常让多个候选都能用 10.50pt 放下，评分会把“更充分使用用户设定的间距范围”与“舒适目标偏差”一起比较；如果利用率权重较高，结果会向较松的间距档移动，但不能超过用户设定的上限。中等简历可能在舒适目标档下需要轻微降字号；联合评分会在“小幅缩字、保持舒适空隙”和“保持大字、压紧部分间距”之间，同时考虑剩余白纸后取舍。长简历会在全部间距下限的候选和较小字号、舒适间距的候选间比较，避免因固定流程必然挤在最小间距；究竟选择哪边由用户确认的权重决定。若即使 8.50pt 和全部最小间距仍超高，就按 L-08 暂停 PDF、完整保留稿件。少数超长条目仍按原定栏宽自然换行，不改写或改变结构。

### 页面利用率和底部留白：两种目标的风险

**尽量铺满（将底部白纸压到接近 0）**符合用户“尽量利用我设定的范围”的方向，也能避免短稿只占页面上半部、下半部空很多的情况。它的风险是为了降低剩余白纸而把间距推到上限，可能让要点和分区被拉散；即使每个参数没有越界，整张简历也可能显得松、断、像被强行撑高。不同间距的上限不是等价的“填充材料”，不能只选择最容易增加高度的那项。

**保留底部舒适区（设定一个允许的剩余白纸区间）**更容易保住版面呼吸感，避免末尾贴近纸边；但若舒适区设得过大，短稿会长期留下明显空白，可能与用户希望尽量利用设置范围的目标相冲突。这个区间不能从 9mm 下边距推导：下边距是纸张边界，内容结束后的剩余白纸是排版结果。

需要用户凭实际纸面审美确认的量是**可接受的底部剩余白纸目标/范围**，以及“页面利用率”相对正文大小、行间节奏、要点和分区层级的优先级。若暂未确认，审查阶段建议把“更充分利用已设定范围”作为候选偏好保留在评分中，并把接近铺满与留有舒适白纸的结果并排展示；若必须选一个临时评估默认，则采用**软性利用率目标**：在参数不越过用户范围、正文不低于8.50pt、间距没有明显松散的前提下优先减少过大的底部白纸，但不要求余白精确为零。此项只是评审/原型假设，不能直接作为正式产品规则。

### 方案三：受限多目标评分，在可行版式中选整体代价最低者

把字号保护、间距偏离舒适值、层级比例、内容高度和布局变化稳定性写成一组明确评分。先排除违反硬约束的组合，再在可行组合中选分数最低的一组。四种间距分别有理想值/容许范围和权重；评分必须由用户评审后定权重，不能伪装成科学客观分。

一种可读的形式是：

```text
硬约束：完整排版；8.50 <= s <= 10.50；间距各自处于已确认边界；H(s,g) <= 279mm

总代价 J =
    w字号 × (10.50 - s)^2
  + w行距 × 偏离行距目标的代价
  + w要点 × 偏离要点目标的代价
  + w分区 × 偏离分区目标的代价
  + w底部 × 不合意的底部剩余白纸代价（目标可为接近铺满或舒适区）
  + w变化 × 相对上一个已提交布局的视觉变化代价

在硬约束内选 J 最小的组合；若无可行组合则保留全文并暂停 PDF。
```

这里不建议把“页面剩余高度越少分越高”当作唯一目标；同时也不能把底部白纸从目标里完全排除，因为用户已经表达希望尽量利用设定范围。可比较两种评分：A 将剩余白纸向 0mm 压近；B 只惩罚超出某个舒适区间的部分。目标值、舒适区和权重都需要用户确认。变化代价只用于编辑过程的稳定性，最终保存/导出仍应按确定规则求出唯一布局，保证同一稿件得到同一 PDF。

全量穷举 201 个字号 × 四个间距各 101 档约 21 亿种组合，不适合每次键入都跑。实用做法是先对字号做有界搜索，再用少量候选档/坐标搜索或束搜索近似优化；每个候选用实际排版器测量。Knuth–Plass 的原论文说明了用候选断行、代价和整体比较来找版面的思路，但它解决的是段落断行，不能证明这里的权重或简历审美分数有效。[Knuth–Plass 原论文](https://gwern.net/doc/design/typography/tex/1981-knuth.pdf)

**优点**：可表达不同间距的不同价值，也能明确控制底部留白与减少版面跳变；有机会在“只分几个档”和“固定先后顺序”之间找到更贴近个稿的平衡。

**缺点**：权重、目标区间和变化惩罚很难选，结果可能准确地优化了错误偏好；解释成“分数最低”不如讲清楚实际视觉影响；近似搜索可能找不到真正最低分。

**可解释性**：中低。可以列出选中原因和各项贡献，但普通用户不应被要求理解权重。若无法把结果说成简单理由，就不适合作为首版默认算法。

**性能和抖动风险**：中到高。需控制候选数量、缓存测量、编辑过程稳定性惩罚；评分相近的候选可能在每次输入后互相抢胜，产生字号/留白来回切换。采用确定性 tie-break、迟滞（只有收益超过门槛才换布局）可缓解，但门槛本身也是待定规则。

**极端内容**：短稿的评分若奖励填满页面会自动拉散，因此必须设计“底部留白舒适区”或空白不罚；长稿在硬约束外没有可行解时必须失败关闭，不可让评分用缩到下限以下或丢字换取低分。单条超长造成极高高度时，要明确接受暂停导出，不应由评分偷偷改布局结构。

## 推荐意见（仍是审查建议）

**建议优先讨论修正版方案二：联合搜索字号、四类间距和页面利用率。** 自我复核确认，先把间距压到下限再求最大字号有结构性偏置；上一轮修正版虽解决了长稿挤在最小间距的问题，却把剩余白纸排除在评分外，也没有充分落实用户“尽量利用设定范围”的方向。新版把底部剩余白纸作为明确可选目标，与字号和四类间距一起比较，因此短稿也可能主动放宽间距来更充分使用页面，同时保留“不要为了填满而明显拉散”的约束。

推荐仍有前提：用户需要确认底部剩余白纸的目标/可接受区间，以及页面利用率、字号和间距层级之间的权重；间距舒适目标和类别权重也待定。尚未确认前，评审暂以“软性利用率目标”比较候选：尽量减少过大空白，但不要求贴边或 0mm 余白；同时保留“铺满”和“舒适留白”两种纸面结果供审美选择。此临时偏好仍只是审查建议，不是产品规则。如果不想确定连续权重，方案一固定档位并列出每档剩余白纸会更容易人工决策；若未来确有更完整的留白、层级和稳定性目标，再评估方案三。

对于“正文缩小伤可读性”的问题，本稿只建议把较大字号作为优先目标；不把 8.50pt 说成普适可读下限。现有 8.50pt 是用户确认的产品保护边界。公开实验研究指出字号与行距会影响阅读速度/理解，但相关研究对象是在线文本，实验建议不能直接推导出这份 A4 简历的最佳字号。[Rello 与 Bigham 的原始研究《Make It Big!》](https://pielot.org/pubs/Rello2016-Fontsize.pdf)

## 需要用户最终决定的开放问题

1. 四种间距各自的舒适目标是什么？最小值和最大值仍未冻结。
2. 用户希望尽量利用已设范围；剩余白纸应尽量接近 0mm，还是保留一个舒适区？可接受的目标或区间是多少？
3. 页面利用率与字号、行间节奏、要点、分区层级冲突时，各自权重如何排序？
4. 字号与间距冲突时，愿意用多少字号换取更舒服的间距？各类别权重如何排序？
5. 是否接受方案二用紧凑/舒适/舒展三档近似连续范围，还是偏好方案一的少量完整版式快照？
6. 实时更新采用每次键入立即重排，还是短暂缓冲后更新？对临界点附近的变化是否接受自动跳档？
7. 编辑器的输入中间态是否立即参与适配？导出前同步计算最终布局必须明确，以保证编辑器与 PDF 一致。
8. 若 81 组候选布局的测量速度达不到实时要求，是否接受先用少量候选即时更新、再补算精细候选？这会影响是否可在编辑中显示暂定布局。

## 技术来源及其支持范围

这里只把一手规范和原始论文用于支持它们直接说明的技术事实，不把它们当作产品决策：

- [W3C CSS Paged Media Level 3](https://www.w3.org/TR/css-page-3/)：页面版面是有限矩形区域，可声明纸张尺寸和页边距；支持“要以真实页面盒测量”的论点，不规定简历应铺满页面。
- [W3C CSS 2.2：行高计算](https://www.w3.org/TR/CSS22/visudet.html#leading) 与 [W3C CSS Inline Layout Level 3：字体度量](https://www.w3.org/TR/css-inline-3/#ascent-and-descent-metrics)：文本行框高度由字体上升/下降度量和行高参与决定；支持不能只靠字符数估高。
- [W3C CSS Box Alignment Level 3：分布对齐](https://www.w3.org/TR/css-align-3/#distribution-values)：`space-between` 等机制如何分配剩余空间；支持“均分空间是一种对齐定义”，不支持“该策略必然审美最好”。
- [Knuth 与 Plass, *Breaking Paragraphs into Lines* (1981)](https://gwern.net/doc/design/typography/tex/1981-knuth.pdf) 与 [Knuth 的 TeX 源码](https://www-cs-faculty.stanford.edu/~knuth/programs/tex.web)：排版候选、空间伸缩和代价比较的原始方法；支持多目标显式化和整体比较的类比，不直接支持简历用的权重。
- [Rello 与 Bigham, *Make It Big!*](https://pielot.org/pubs/Rello2016-Fontsize.pdf)：在线文本阅读实验报告字号与行距对可读性的影响；只支持“字号/行距会影响阅读体验”，研究场景不能给出这份纸面简历的最佳数值。
