# Resume 抽离设计讨论

日期：2026-10-10。状态：需求访谈与来源调查记录，不是已批准的实施规格。产品行为、约束和后续功能变更统一维护在根目录`SPEC.md`。

## 用户已明确的目标

- 将 Career-Next 和旧 Career 的简历相关能力抽离到独立 Resume 项目，最终交付一个 App。
- Resume 是高优先级、快节奏项目，要尽快用于真实工作。
- Career-Next 继续长期优化；Resume 的生产使用经验可能形成回馈。

## 本次来源读取范围

本次用户明确授权两个项目的简历模块抽离。调查只读简历源码、直接依赖与相关验收文档，不据此把旧实现引入 Career-Next，不修改其冻结产品或架构正文。

第一轮源码调查未读取真实用户数据库、简历正文或凭据，未调用外部服务。第二轮用户指定两条来源链接并授权以妙搭稿为初稿、从本机简历补入 GitHub；已只读查看指定本机简历页面、妙搭应用详情、开发记录及实际简历预览。没有源应用保存、版本、导出、发布或删除操作，没有 AI 调用。源项目已有未提交改动，必须保留；调查按当前工作树进行。

## 初步源码事实

- Career-Next 的简历文稿、编辑器、保存会话、命名版本及可信 PDF 链可作为抽离基础。入口：`packages/contracts/resume/`、`packages/frontend/features/resume/`、`packages/backend/domains/resume/`、`apps/desktop/capabilities/headless-pdf.ts`。
- Career-Next 当前文稿以 Opportunity 为归属，一机会至多一份当前稿；身份信息由共享 Profile 维护。独立产品需要重新明确简历创建、列表和归属，以及身份共享规则。
- Career-Next 的 AI 简历提案会组合机会、公司、JD 与研究上下文，不能直接复制整个运行装配作为独立 App。
- 旧 Career 具备纸面编辑、自动保存、命名版本、PDF、恢复、逐条 AI 建议与按需职业素材检索；简历和 AI 上下文同样依赖原 Career 业务对象及存储。
- 旧 Career 屏幕纸面和 ReportLab PDF 使用不同排版实现，打印代码不读取文稿对齐记录，因此不能承诺纸面与 PDF 完全一致。另有 Markdown/JSON 导出，未发现 DOCX 导出或外部 JSON 导入能力。
- Career-Next 当前 `.app` 是本机 Node 后台配合 Chrome 的启动器。独立原生窗口或面向其他用户分发需要另行确定；现有签名、公证和 x64 尚未验收。
- 新近单 A4 纸面已有保存、重开与 PDF 字符验证证据；界面人工审批和周边 Gemini 改动尚未最终通过。旧项目真实 Resume AI 语义质量也不能视为已经验证。

事实由两项只读简历范围调查获得；没有运行独立 Resume 验收。调查结果用于选择首版方案，不构成生产可用声明。

下一步建议以 Career-Next 的文档、保存与 PDF 链为基础，按首版需要补入旧 Career 有价值的交互和能力。首版不携带两边 AI、职业上下文或机会系统。此为待讨论的抽离方案，尚未复制代码。

## 第一轮已确认

用户选择：

1. 仅本人在当前 Mac 上使用本地 App，立即用于真实求职。
2. 首轮包含简历编辑、保存、多份简历、命名版本、PDF 和选中文字 AI 改写；第二轮用户明确取消全部 AI 接入，以第二轮为准。
3. Resume 与 Career-Next 各自独立保存资料、独立发版，经验人工反馈；首版不做自动数据同步。

## 第二轮已确认

4. 双击 Resume.app，打开 Chrome 专用应用窗口，不显示地址栏。
5. 轻量简历列表，可快速格式化、修改和产出，不需先建立公司/岗位。
6. 每份简历姓名、联系方式和链接独立，复制时一起复制，不同步其他当前简历。
7. 单张 A4 纸面，基于指定妙搭来源进一步优化，字体、字号、排版布局需要继续确定。
8. 指定妙搭稿作为原始初稿版本；从指定本机简历补入 GitHub 白猫图标和链接。GitHub 是随时可取消的可选项，不是候补链接；移除时不保留图标、链接、分隔符或空位。个人资料留在本机用户数据/私密采集目录，不嵌入发布包或提交源码。
9. 超过一页时缩小文字保持一页，取代此前推荐的自然分页。具体缩小方式和排版控制继续确认。
10. 首版完全不接 AI；用户自行拿 PDF 或截图去外部 AI 咨询优化。不配置模型、不积累 agent 上下文。

## 实际来源版面基线

2026-10-10 通过实际预览的渲染 DOM 只读取得：

- A4 固定宽度约793.7px，页边距约34.0px，即约9mm。
- 中文字体栈为 Source Han Sans CN Local / Source Han Sans SC / PingFang SC；英语及数字字体栈优先 Times New Roman。这是 CSS 请求的字体栈，不等于已核验每个字实际使用的字体文件。
- 姓名24px（18pt）；分区标题16px（12pt）；联系方式12px（9pt）。
- 正文11.8212px（约8.87pt），行距16.5497px；条目标题与日期12.3038px（约9.23pt）。当前适配系数0.965，界面显示缩放97%。
- 来源的空职责和空日期提示不是正文事实，不替用户补写，不应打印为占位文字。
- 旧 Career 的单页适配通过二分测量可用高度，调整正文/条目字号，行距随字号变化，部分间距同比变化；姓名、联系方式、分区标题和图标不整体缩放。该方式可作为首版单页适配参考；独立 Resume 的屏幕与 PDF 必须采用一致规则，不能继承旧项目两套排版的偏差。

首版需核对屏幕、保存重开与 PDF 的同一内容/排版，而非只验证页面外观。
