## 0. 边界：什么能动，什么不能动

**冻结不变（SPEC 已确认）：**

## 1. 设计输入

### 1.1 品类与标杆

品类：**浏览器侧边栏里的文书工具**——同时具备三种基因：侧边栏实用扩展（窄幅、常驻、随叫随到）、文档编辑器（纸面即内容）、版本/方向管理（多稿并行）。标杆从三类里各取一家拆：

| 标杆 | 拆出来的要点 | 对本产品的意义 |
| --- | --- | --- |
| Linear（现代专业工具） | 近单色 + 单一强调色；1px 分隔线而非阴影与间距；数据面零圆角、只有交互件与浮层有圆角；键盘优先、约 200ms ease-out；内联反馈、无转圈；LCH 感知均匀色彩、主题仅 3 组变量 | "工具完成度"的地板：定义了侧边栏里高密度却不乱的画法 |
| iA Writer / Ulysses（文书工具） | 纸面是唯一主角，chrome 退到近乎消失；资料库是"分组列表"而非卡片墙；编辑区专注模式 | "文书工具"的正确姿势：UI 不与内容争注意力 |
| 编辑部/书籍装帧（印刷传统） | 刊头、目录页、folio 页码、细规则线分区、校对红、双线 | 本产品与"付印"的真实关系：整款工具服务于一张要打印的纸 |

> 标杆栏为凭记忆与公开设计资料整理，**未取实时截图核验**；字体、色彩、主视觉三栏仍需在真机验收时补截图比对。

### 1.2 用户、场景与任务

- 用户：求职者本人，首版在本人 Mac + Chrome 自用；正在维护多个投递方向，改稿频繁、周期长
- 场景：Chrome 侧边栏（宽度约 320–800px，当前实现有 620/900px 两档响应式）；长时间专注编辑；随时打印导出
- 情绪与约束：简历是"要拿出去被评判的纸"，用户要的是**控制感与确定性**（自动保存真的在存、超页真的会拦、打印真的只出 A4），不是玩具感；数据纯本机，隐私敏感
- 主动作（按频率）：① 在纸面上改字 ② 切方向（⌘F）③ 打印 PDF ④ 新建/改名方向 ⑤ 撤销

### 1.3 调性（五刻度）

编辑是专注正事 → 能量取**安静**；产品自己按 mm/pt 精度工作 → 完成度取**精致**；侧边栏窄 → 密度取**中**；文书工具 → 分量取**轻**；求职是正事 → 严肃度取**庄重**。方向 A 落在"安静 × 精致 × 中密度 × 轻 × 庄重"这一格——最保守、也最不会错的一格。

## 2. 方向 A · 极简专业「纸面工坊」

**北极星：** 让 A4 纸是整间屋子里唯一的主角，其余一切像一张收拾干净的灰卡纸工作台。

**核心思路：** 删到不能再删。chrome 全部退为 1px 发丝线、白面与暖灰底的三层结构；彩色只保留一个"墨蓝"强调色，面积不超过画面 5%；唯一的投影给纸面——因为它真的是"放在台面上的一张纸"。

**生成引擎：** 材质 × 环境——灰卡纸工作台 + 一叠待打印的 A4 纸。圆角、描边、阴影的尺度都从"纸和台面"推出：控件圆角 8px（纸张的柔），投影只给纸（台面上的实物）。

**骨架与信息层级：** 顶栏一行（左：方向名；中：缩放胶囊；右：打印 PDF）→ 纸面居中占据全部剩余空间。方向室 = 窄栏单列、宽栏双列 A4 缩略图网格（沿用 S-07 已确认结构），卡片即"一张小纸"，用细边与轻投影收住纸面；名称可直接点按改名，右上角只放删除按钮。当前方向用低调的墨蓝边框提示，不加状态文字。首屏第一眼必须是纸，不是按钮。

> 方向室**没有顶栏按钮**：入口是 ⌘F（SPEC P-03/S-07 冻结快捷键，见 §3 可用性基线第 1 条）。round 06 实装时漏掉了这一步，顶栏保留了"方向室"按钮；round 09 按首屏设计稿 `a-paper-bench.html` 收敛为单个 PDF 主动作。

**色彩规范：**

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| 台面底 | `#F4F3F1` | 纸面外背景、纸面滚动区 |
| 面 | `#FFFFFF` | 顶栏、弹窗、控件底 |
| 墨 | `#23222A` | 主文字、主按钮 |
| 次 | `#6E6A75` | 辅助文字、占位符 |
| 线 | `#E3E1DC` | 1px 分隔、控件描边 |
| 强调（墨蓝） | `#3D5A80` | 主动作、选中态、焦点环 |
| 选中底 | `#E9EEF4` | 列表/控件选中背景 |
| 成功 | `#3E7C4F` | toast 成功态 |
| 危险 | `#B3382F` | 删除确认、超页边界 |

**字体规范：** 界面 PingFang SC；方向名 16px/600，正文 13px/400，辅助 11px/400；所有数字（缩放比例、时间戳）`font-variant-numeric: tabular-nums`。字重只有 400/600 两档，层级靠字号与灰度不靠彩色。

**关键元素处理：**

- **顶栏**：白底、底部 1px 发丝线，三栏 `grid minmax(0,1fr) auto minmax(0,1fr)`——左方向名，中缩放胶囊，右打印 PDF；方向名点击即改（悬停极淡底色 `#F7F6F4` + 文字光标）。保存状态流转已按用户要求移除（round 10），自动保存静默进行，失败仅 toast 提示
- **纸面**：`box-shadow: 0 1px 2px #23222A14, 0 12px 32px -8px #23222A1F`——整站唯一阴影；滚动区即台面底色
- **缩放胶囊**：白底 1px 边 8px 圆角，`− 50% ＋`——读数实时显示当前缩放比例（不是"整页"字样）；默认整页、无 100% 档，读数点击即重置为整页；"虚线框"为 SPEC L-12 正文范围参考线开关，与缩放同处一胶囊但不是缩放模式
- **方向室卡片**：白面、细边与轻投影；名称 14–16px/600，点击名称直接改名；无“当前方向”“最近编辑”文字，时间戳单独显示并使用等宽数字；右上角只保留 34×34 删除按钮，使用用户指定的 `🗑️` 图标，悬停给出克制的危险态
- **弹窗/toast**：白面 1px 边 8px 圆角；toast 底部居中、墨底白字、无图标
- **排序手柄**：32px 白底方钮 1px 边。拖动时原条目原地保留占位（隐藏不脱离布局，**整页零重排**），一个 fixed 克隆体（ghost）跟随指针，2px 墨蓝插入指示线显示落点；松手才一次性重排并同步数据，不再重建整页——这是为根除"拖动卡顿"做的架构调整（此前每帧实时搬动真实条目 + 松手整页重建，长简历尤其卡）
- **超页边界**：`#B3382F` 校对红 + "暂停打印"小条
- **联系添加菜单**：白底 1px 边小浮层，12px 文字，无阴影

**交互流程与反馈：** ⌘F 开合方向室用 120ms 淡入 + 纸面轻微后退感（不改动纸面本身）；新建方向弹窗内命名框自动聚焦；删除确认二次点击；缩放点击即改、读数直接跳字；全部反馈"当场发生"，不加 Toast 噪音。保存失败 toast 带重试入口。

**组件一致性规则：** 圆角以控件 8–10px、卡片 14px、纸面 2px 为主；描边以 1px 发丝线为主；阴影只允许纸面与卡片；动效全场 120–160ms ease-out；操作图标优先用线性单色，删除按钮按用户指定使用 `🗑️`。

**记忆点：** 双击纸面外任意处进入"只留纸"的专注态（顶栏与胶囊淡出 60%），动一下鼠标回来——不新增快捷键，符合 E-06。

**放弃：** 彩色标签、大圆角、渐变、玻璃拟态、非必要 emoji、暗色。

## 3. 可用性基线（必须守住）

1. 快捷键不新增、行为不变：⌘F 方向室、⌘Z 撤销、⌘B 加粗、Esc 返回；不提供 ⌘S（§5/E-05/E-06）
2. 纸面 9mm 边距、虚线框只显示/隐藏正文范围（L-12）、L-19 排版与字号范围不被任何视觉改动触碰
3. 保存状态真实可查，失败保留输入 + 原因 + 重试（S-02）；中文输入法 composition 期间不保存半句（E-04）
4. 方向室信息不省略：名称、无前缀的分钟级时间、A4 缩略图、搜索、点击名称改名、新建、删除（S-07）；窄栏一列宽栏多列；不显示“当前方向”“最近编辑”标签
5. 焦点可见（focus-visible 环，3px 或等效）、正文对比 ≥ 4.5:1、辅助 ≥ 3:1；数字一律 tabular-nums
6. `@media print` 仅输出 A4、隐藏全部 UI；任何装饰元素都不得渗入打印
7. 空列表的编辑补充入口仅编辑时出现、不打印（E-06）；空字段与界面提示不进 PDF（D-07）
8. 零新增依赖：纯 HTML/CSS/JS 改造，主题用 CSS 自定义属性分层，不做构建期魔法
9. 所有动效在 `prefers-reduced-motion: reduce` 下降级为淡入淡出
10. 画面不出现"示例/示意图/未接入"类制作说明；演示数据用虚构稿

## 8. 联系图标：光学归一 + 首屏纸面对齐 v34（round 05）

**① 光学归一（改渲染、不动美术）：** 四个描边图标用 `24×24` viewBox 自带内边距，白猫用 `16×16` 且路径几乎填满；同处 14px 容器 → 墨迹尺寸参差（电话 83%、邮箱高度 54%、白猫近 100%）。方案是把每个图标的墨迹盒映射到一个居中的正方形 viewBox，美术路径一字不动。早期用根 `<svg>` 的 `transform` 属性在 Chrome 不可靠，改用 **viewBox 重写**后稳定。

**② 首屏纸面改为 v34 抽取源：** round 01 首屏纸面是手搓简化版（下边框标题、Times 衬线、4px 圆点 bullet、硬三栏），与 v34 真实渲染不符。用 `extract-v34.cjs` 从 v34 抽取渲染后的 `#paper-content` innerHTML + 精选纸面 CSS（白名单剥离编辑器交互态），注入首屏。现为 v34 真实结构：section 深灰胶囊标签、entry-head 三栏（岗位｜公司｜日期）、`•` CSS bullets、run-zh/en/num 字体分轨、`｜` 全角分隔符。

## 9. 方向 A 实装到扩展（round 06）

**首屏侧：** 移除右下角 view-dock，缩放胶囊（`− 整页 ＋ 虚线框`）入顶栏 grid 中列真居中；默认整页、无 100% 档。

**扩展侧：**

- 主题迁移：`:root` 建立方向 A 语义变量（`--accent #3D5A80` / `--bench #F4F3F1` / `--surface` / `--line #E3E1DC` / `--ink #23222A` / `--selected #E9EEF4` / `--saved` / `--danger #B3382F`），紫色 hex 清零；纸面冻结色（`#424242` 胶囊、`#252525` 正文等）未动
- 缩放控件：删 `view-segment`（整页|100% 分段）与 `viewMode='actual'` 逻辑，`viewMode` 固定 fit，`zoom-readout` 点击重置为整页（当时显示"整页"字样，round 10 改为实时百分比）；控件入顶栏中列（实测居中偏差 0px）
- 编辑/删除按钮：方向室最初采用铅笔（改名）+ 垃圾桶（删除）一对操作钮；2026-10-23 用户决定改为点击名称改名，并将删除图标指定为 `🗑️`，不再保留铅笔按钮或状态标签

**验证：** `shoot-extension.cjs`（playwright + 本地 http 渲染 `sidepanel.html`，localStorage 种 3 个方向）实测：顶栏居中 offset=0（当时 readout 显示"整页"，round 10 起为实时百分比）、9 个 CSS 变量全部解析、按钮几何 28×28 与 hover 语义色正确；扩展测试 13/13 PASS；`dist-extension/` 重建无残留。

## 10. 联系图标定稿 9×9px（round 07 → round 08 修正）

**尺寸口径：** 首屏预览整体 `scale(.68)`，屏幕要显示 9px → 首屏 CSS 容器 **13.235px**（9÷0.68）；v34 真实 PDF 容器 **9px** @100%。两者渲染到屏幕都是 9×9px。

**round 07（有缺陷，已修正）：** 当时用 `getBBox()` 的**几何框**当 viewBox，边长只等于图形路径的几何范围。但 `getBBox()` **不含描边**——描边有半个宽度落在 viewBox 外面，被 SVG 视口裁掉。对圆形图标（微信、个人网站、电话外弧）等于把整圈描边切掉一半，肉眼就是"墨水变浅、边缘发平"。

**round 08 修正：** viewBox 改为**含描边的墨迹框**——几何框四边各外扩描边半宽（普通图标 0.9，微信因 `scale(1.2)` 外扩 1.08），白猫是实心填充不外扩。

## 15. 拖拽改版：空位框 + 让位重排（round 12）

用户反馈：**"这个拖拽模式不直观，我要知道我拖拽过去替代的是哪一行"**——并给出了明确诉求：*从第二行拖到第一行时，第一行应该让位到第二行，第一行留下空白位置框给正在 hover 的这一行*。

### 旧方案为什么不直观

上一版（round 11 续的 ghost + 指示线）是这样画的：被拖条目 `visibility:hidden`（**隐形坑**，只占位不显形）+ 一条 2px 墨蓝指示线标落点 + 一个跟随指针的克隆体（ghost）。

问题出在前两者：
- **隐形坑看不出"这里空着"**——它只是"看不见的一块空间"，用户无法判断那是不是一个可落位的空位；
- **2px 细线说不清"替代的是哪一行"**——线只告诉你"插在两个行之间"，不告诉你"这行会被顶到哪儿去"。

### 新方案：让被拖条目自己变成"空位框"

1. **被拖条目就地变成空位框**（`extension/sidepanel.css`）
   `.sortable.drag-source > *{visibility:hidden}` —— 只隐藏**内容**、保留条目自己的盒子（`visibility` 不影响布局，纸面总高不变，不会扰动 L-19 自动排版）；再用 `::after` 画 2px 墨蓝虚线描边 + 浅墨蓝底。看上去就是一格明明白白的空位。
2. **其余条目围着空位框实时重排（让位）**
   拖动期把**真实条目**在 DOM 里搬到落点（`insertBefore`），于是指针指向的那一行**当场往下让开**，空位框停在它的位置上。这就是用户要的那一幕：第 2 行拖向第 1 行时，第 1 行滑到第 2 行，第 1 行原位留下空位框。
3. **极简：不出现任何文字浮标**（`extension/sidepanel.css` / `extension/sidepanel.mjs`）
   初版曾在空位框左上角加墨蓝小胶囊"松手放到这里"，但这句话与极简设计理念冲突，已整体移除（`.drop-hint` 元素与对应 CSS 一并删除）。如今"会落到哪一格、要替代的是哪一行"完全由**空位框本身**（虚线描边的可见占位格 + 目标行实时让位）表达，不需要任何文字说明。
4. **2px 指示线删除**——它表达的"插在两行之间"已经被空位框完整表达，保留只会多一层噪声。
5. **手柄跟着空位框走**（`followHandleToFrame`），不再留在原地和真正要落的位置脱节。

### 落点规则

指针落在某行**上半部** → 插到它之前（那行让位下移）；落在**下半部** → 落到它之后；越过末行 → 排到末尾。位置没变就不 `insertBefore`（避免无谓重排），rAF 节流每帧最多算一次。

### 数据与撤销

起拖时记下 `originalIds`；松手后与当前 DOM 顺序比对——没变就不记撤销、不落盘；变了则按 DOM 顺序重排数据（`pushUndo` → 改数据 → `scheduleFit` + `scheduleSave`）。仍然不 `renderPaper()`：DOM 顺序在拖动期已是最终顺序，重建整页只会带来销毁+重建全部 contenteditable 的大开销和一次界面闪。

### 验证

无头 Chrome（CDP 真实鼠标事件序列）专项 15/15：空位框可见（自身 visible / 子节点 hidden）、虚线描边、**指向行让位**、提示牌 z 高于 ghost、ghost 宽度与行一致（425=425，不被放大）、要点与经历两种列表都正确、上/下半部落点规则、向下跨行、原地方下不变、顺序落盘；控制台零异常。截图 `shots/ext-drag-slot.png`（要点）、`shots/ext-drag-experience.png`（经历）。

**操作提示**：要拖**整段经历**，悬停在它的三栏表头上（块中央是它自己的要点列表，那里是另一个可排项）；要拖**某条要点**，悬停在该要点上即可。
