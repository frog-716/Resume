# ADR-0003：Chrome 侧边栏与简历方向

状态：已确认，先实现并实际试用
日期：2026-10-19

## 背景

原首版按独立 Mac App 设计，使用一个自动保存当前稿、多个只读快照和本机服务导出 PDF。用户重新评估后确认：真实使用时主要是在 Chrome 中边看网页、边编辑简历；独立 App 的启动和切换成本不值得保留。

## 决策

1. Resume 首版改为 Chrome Manifest V3 侧边栏扩展。
2. 侧边栏是唯一编辑表面，不增加完整编辑标签页。
3. 首版不读取网页、不申请网站权限、不接入 AI、不控制 AI 网页。
4. 业务对象从“当前稿＋快照”改为多个命名的“简历方向”。
5. 每个方向只有一个自动保存当前稿；从已有方向复制模板后独立演进。
6. 至少保留一个方向；删除前确认，删除后不可恢复；不设置快照、废纸篓或历史版本。
7. `⌘F` 打开简历方向室；不再提供应用 `⌘S`。当前方向自动保存，`⌘Z`只负责当前编辑会话撤销。
8. PDF 使用 Chrome 自带打印。用户在打印界面选择“另存为 PDF”；扩展不承诺静默保存 Downloads 或自动处理文件名冲突。
9. 侧边栏宽度由 Chrome 和用户控制，扩展不承诺设置精确打开宽度。整页、100%和显示比例微调只影响屏幕观看，不改变 A4 排版和 PDF。
10. L-19 自动排版、A4、字体、字段结构和编辑快捷键继续作为稳定领域规则；扩展平台能力通过适配代码接入，不进入领域规则。

## 取舍

### 放弃

- 关闭后回到历史版本；
- 用户可见的快照和废纸篓；
- 独立 Mac App、原生启动器和本机 Node 服务运行依赖；
- 通过程序读取或修改 ChatGPT、Claude 等网页；
- 静默写入 Downloads 的 PDF 导出流程。

### 保留

- 四个固定板块；
- 复制方向后的独立正文、身份、链接和布局；
- A4 单页自动适配和超页暂停打印；
- 中文输入、快捷键、撤销、排序、自动保存；
- PDF 中的可选文字和可点击链接，具体以 Chrome 打印实际验收为准。

## 边界

- `extension/sidepanel.mjs` 负责方向室、纸面编辑、自动保存、观看缩放和打印调用。
- `extension/domain-auto-layout.mjs`、`extension/domain-resume-content.mjs` 和 `extension/text-runs.mjs` 提供扩展侧的规则与渲染支持。
- `extension/service-worker.js` 只负责点击扩展图标后打开侧边栏，不保存业务状态。
- `chrome.storage.local` 是扩展本地数据的持久化边界；业务状态不放在 Service Worker 内存中。
- `src/`、`server/`、`web/` 仍保留旧本机 App 实现及测试资料，但不作为侧边栏扩展的运行依赖。

## 验收门

先加载 `extension/` 进行真实试用，再决定是否优化：

1. 侧边栏宽度较小时仍能输入和保存；整页、100%与缩放可用。
2. 中文输入法组合输入不丢字、不跳光标。
3. `⌘F`、`Esc`、`⌘Z` 在真实侧边栏中行为可接受；不要求 `⌘S`。
4. 新建方向、模板复制、改名、删除和至少保留一个方向正常。
5. 关闭侧边栏再打开后恢复最后一次成功保存内容。
6. Chrome 打印产生 A4 结果，超页时不误导用户已完成导出。

未通过这些验收前，不引入网页读取、AI Provider、云同步或更复杂的导出架构。
