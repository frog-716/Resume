## 0. 一句话任务

在一个**全新文件夹**中，按已冻结规格 clean-room 重写 Resume 首版：**单用户、本机、无 AI、无同步、单张 A4、自动保存当前稿、仅 PDF 导出**的 Mac 应用。产品行为以 `SPEC.md` 为唯一正本，不得增减。当前仓库（含全部旧代码）仅作仲裁参考。

## 1. 开工前必读（按顺序）

1. `SPEC.md` — 产品行为唯一正本。只实现标"已确认 / 已确认、冻结"的规则；"待确认建议"不生效。
2. `MAP.md` — 仓库结构与当前状态。
3. `docs/adr/0001-independent-delivery.md`、`docs/adr/0002-resume-owned-identity.md` — 两项工程决策。
4. `docs/review/spacing-eight-gaps-adversarial-20261016.md` — L-19 冻结算法的推导与审查记录。
5. `prototypes/a4-spacing-eight-gaps-demo-v34.html` — 视觉参考，**不是规格**。

## 2. 旧代码的法律地位

- `src/`、`server/`、`web/`、`prototypes/`、`design-handoff/`：**仲裁参考，不是模板**。不复制源码；规格有歧义时，以旧实现的行为为准据。
- Demo 中实测的像素常数（如 18.5px、`top:-12.89473684px`、行高 1.36 等比例以外的测量值）是旧渲染模型下的产物：**新架构必须重新实测校准，禁止照抄**。
- "不参考旧代码"的法律定义：**不继承源码，必须继承行为**（行为以可执行验收用例固化）。

## 3. 硬边界（五条，不可谈判）

### B1 正本源权
- `SPEC.md` = 产品行为唯一正本；`MAP.md` = 结构；`docs/adr/` = 技术决策；Demo、历史讨论、素材资料、个人直觉 = 参考。
- 规则冲突：**停止实现，报告用户裁决。不允许自行猜测；不允许修改 SPEC 已确认规则。**

### B2 预言机与数据
- M0 阶段（不写产品代码）：把每条已确认规则转成合成验收用例；以真实妙搭稿的当前输出固化为 golden 语料。**没有验收用例的功能不进 MVP。**
- 数据迁移二选一，开工前由用户拍板并写进 README：①不迁移，首装空库；②定义独立导入格式 + 一次性导入器。**禁止"以后再考虑"。**

### B3 架构边界

```
domain       纯业务规则：内容、撤销、自动排版（无 IO）
application  用例：编辑、保存、快照、导出
adapters     本地存储、PDF、时间、ID
ui           输入与展示
```

- `domain` 不依赖 UI、文件系统、数据库、任何 Agent harness。
- 屏幕预览与 PDF 必须消费**同一个已解析排版结果**（一条不变量，必须有测试）。
- 默认使用一个版本化本地存储；没有可复现的容量、查询或事务问题，不引入数据库/ORM。
- 每个模块必须有当前调用方、明确不变量和测试；**没有调用方的模块禁止存在**。
- 引入新依赖必须说明它解决哪个当前验收问题；不确定时选更无聊的。
- "教科书级"是验收后的结果，不是架构输入。

### B4 协作契约
- 产品运行时不依赖任何 harness；**不围绕 Pi / Codex 的 API 设计应用结构**（其 API 会变，耦合即导入别人的发布周期）。
- 仓库只暴露 `check` / `test` / `build` 三个命令，一切验证经它们。
- 同一份契约、Schema、排版公式只能有一个写入者；契约变更必须串行并经用户确认。
- 每个模块入口写明：输入、输出、错误、不变量、测试位置。
- 用"窄接口 + 透明实现 + golden 测试"替代"深模块"。"支撑未来模型"的可验证定义：新 Agent 只读 SPEC + 契约 + 测试，即可正确修改该模块。

### B5 里程碑顺序（不许跳级）

- **M0**：golden 语料 + 数据决策（不动产品代码）。
- **M1**：domain 排版内核复现 L-19 冻结算法——全项目唯一未验证的风险，优先做透。
- **M2**：application + UI + PDF 同源闭环（SPEC §7 验收项 1–4、9–11 的主体）。
- **M3**：收藏馆 / 快照 / 撤销 / 废纸篓（规格最完整、风险最低，放最后）。
- 架构深化（分层细化、模块重构）是 M1 通过之后的 refactor 目标，不是重建前提。

## 4. 明确禁止

数据库 / ORM；微服务；远程 API；云同步；AI / LLM 调用；插件 SDK；事件总线；多租户；harness 运行时依赖；为"未来可能有用"创建模块；照抄 Demo 像素常数；自行修改 SPEC 已确认规则；规格冲突时自行裁决。

## 5. 每个里程碑的完成定义

1. `check`、`test`、`build` 三个命令全绿；
2. 对应 SPEC ID 的验收用例全过（M1 起对照 golden 语料，PDF 项按 SPEC §7 第 6、9 条）；
3. 提交报告：改了什么、验证证据、发现的规格歧义（有歧义停下问，不许猜）。
