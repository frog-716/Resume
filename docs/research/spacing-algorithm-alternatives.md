# 独立 Resume 单页 A4 自动排版算法研究

研究日期：2026-10-15。本文只作算法研究，不修改产品规格、项目地图或原型；算法建议不是已确认规则。产品规则以 [`SPEC.md`](../../SPEC.md) 为准。

## 结论先说

新补充的候选方向是**比例联动整体缩放**：先通过纸面确定字号与四种空隙各自的美观比例，再让字号和空隙一起放大或缩小。它比“4种空隙各自乱调”更统一，也符合“空隙跟字号一起变”的想法。比例系数还没有通过纸面确认，所以目前是新候选，不是冻结规则。

正式开发前仍要把两个目标分开：**“尽量贴近页底”可以量出来；“看起来最好看”不能只靠公式算出来。** 可以用真实 A4 页面试排、筛掉超出边界的结果，再找接近页底的候选；但字号与空隙之间的美观比例要先通过真实简历确认，不能把某组权重或“各间距同进度”说成客观审美答案。

这里的 0mm 应当是**最想靠近的目标**，不应成为必须达到、甚至允许越过正文边界的命令：找所有“不超过可写高度”的结果，取剩余白纸最少的一个。字号每次只走0.01pt、文字换行按整行改变，因而有时没有刚好等于0的可行版式。若四种间距都到上限仍有余白，就留着；若最小字号与最窄间距仍超页，就保留全文并暂停 PDF 导出。

本次复核得到三个关键结论：

- 目前的 `spacing()/fit()` 把四种空隙绑在同一条变化轨迹上。它们不会在实际高度里“互相抵消”：各间距增加时都占用纸面。真正的问题是各自出现的次数、每次增加量、视觉作用都不同，却被迫按同一比例走；这会限制算法可选的版面形状。
- 独立 Resume 的真实布局受字号、字体度量、可换行位置和行高共同影响，不能只用字符数估算高度。每个候选都应由同一套页面布局实际试排，再检查联系方式横向是否放得下。
- 固定 18.5px 联系区到首个分区标题的距离是硬约束，不是四种可调间距之一；不能让“铺满”逻辑把它拿来挪动。[`SPEC.md` L-17](../../SPEC.md)

若字号和四种间距各自独立、都按0.01一档，约有**83亿种**组合；这也是独立搜索的成本。按下面“比例联动”的新思路，四种间距都由字号和固定比例算出，只剩201档正文大小可试。每档仍需用真实页面测量，但这个数量可以逐档核对，不必做83亿次组合搜索。

## 一手来源说明了什么

来源事实和本文建议分开：标准可以说明浏览器怎样计算纸面和行框，不能替用户决定哪种简历更好看。

- **打印是有限页面区域。** W3C 的分页规范把每张纸表示成 page box，页面正文流入其 page area；这支持把279mm当作硬容量来实测，不支持把9mm边距当作可用空间。[W3C CSS Paged Media](https://www.w3.org/TR/css-page-3/#page-model)
- **换行和行高会联动影响高度。** CSS Text 说明允许换行的位置由语言和断行规则决定，并在行宽不够时发生软换行；CSS Inline 说明 `line-height` 是行框高度计算的一部分，数字行高还会乘以该元素字号，行框也可能为容纳较高的字体内容而变高。[W3C CSS Text](https://www.w3.org/TR/css-text-3/)、[W3C CSS Inline Layout](https://www.w3.org/TR/css-inline-3/#line-height-property)
- **测量的是布局盒，不是字墨边沿。** v23 用 `getBoundingClientRect()` 读取正文盒高度；CSSOM View 将这个 API 定义为返回元素布局矩形的包围盒。因此“余白0mm”应理解为正文布局盒到可写区域底边的空隙为0，不表示最后一个字的黑色像素碰到边界。行框还包含行高带来的上下空白。[v23 原型](../../prototypes/a4-spacing-algorithm-demo-v23.html)、[W3C CSSOM View](https://www.w3.org/TR/cssom-view/#dom-element-getboundingclientrect)、[W3C CSS Inline Layout](https://www.w3.org/TR/css-inline-3/#line-height-property)
- **pt 与 CSS px 有固定换算。** CSS 规定1pt=1/72英寸、1px=1/96英寸；所以0.01pt约为0.0133 CSS px。0.01pt适合当作内部选择精度，不代表屏幕上能看出这一档，也不能单独证明打印输出的实物尺寸精度。[W3C CSS Values and Units](https://www.w3.org/TR/css-values-3/#absolute-lengths)
- **平均分配剩余空间是另一种明确规则。** CSS Box Alignment 的 `space-between` 把剩余空间平均分到相邻项目之间，并让首尾项目贴齐容器边缘；规范定义了这种分法，没有说它适合简历的行距、要点和分区层级。[W3C CSS Box Alignment](https://www.w3.org/TR/css-align-3/#distribution-values)
- **整段代价比较有排版先例，但不是本产品答案。** Knuth 和 Plass 的原论文介绍用 boxes、glue、penalties 表达排版候选，并用动态规划从段落整体比较断行；论文解决的是段落断行，不是选择简历的正文大小与四种垂直间距，也没有给出 Resume 应采用的权重。[原论文 DOI 页面](https://doi.org/10.1002/spe.4380111102)、[TeX 作者源码](https://cs.stanford.edu/~knuth/programs/tex.web)

## 当前原型与历史候选复核

### 编辑主流程：共享一个进度值

`spacing(body, density)` 把一个0到1的 `density` 同时映射到正文行距、三栏换行行距、要点间距和分区间距；点数间距还乘一个随正文大小变化的系数并限在上下限内。`fit()` 自动模式先用最窄间距测量；放不下时在8.50–当前正文之间找可容纳字号；固定字号后再试最大 `density`，放不下则二分求仍可容纳的进度。[v23 `spacing()` / `fit()`](../../prototypes/a4-spacing-algorithm-demo-v23.html)、[`SPEC.md` L-19](../../SPEC.md)

**优点**是容易讲：“字先缩到能放下，再一起放松四种空隙”；大体上运行步骤少、结果可重复。**主要短板**是把“各自走过本范围的同一百分比”当成“同样的视觉进度”，但该百分比不代表增加相同毫米，也不代表视觉价值相等。正文行距作用在很多行，分区间距只在少数位置；同一行高增量会随行数放大。共享进度可以做一个简单默认值，却无法回答“这次多出来的空间该主要给行距、要点还是分区”。

代码还将要点和分区的点数间距乘以 `k=1+0.5×(正文pt/9.5−1)` 后再夹在上下限内。这意味着在10.50pt时，最窄档可能高于记载的下限；在8.50pt时，最高档可能低于记载上限。此耦合来自当前原型公式，不是 CSS 或排版标准要求。[v23 `spacing()`](../../prototypes/a4-spacing-algorithm-demo-v23.html)

二分搜索只在“字号越大，测得高度不会反而变小”或“共同进度越高，测得高度不会反而变小”的前提下能保证找最大可行值。CSS 断行会使高度出现台阶；台阶本身不妨碍单调二分，但实现应针对实际 PingFang SC、Times New Roman、栏宽和真实内容核验单调性。若不想把正确性押在这项假设上，正文候选只有201档（850到1050个百分之一磅，含端点），逐档试排也容易复核。字号与换行的耦合由 CSS 行宽和字体度量决定，[W3C CSS Text](https://www.w3.org/TR/css-text-3/)；字号和 `line-height` 对行框高度的关系见[W3C CSS Inline Layout](https://www.w3.org/TR/css-inline-3/#line-height-property)。

需要纠正一个容易误会的说法：在正文大小固定时，当前四个间距都随 `density` 增大而增大，几何高度不会因为它们“互相抵消”而变小。问题是**同一个进度锁死四种间距之间的取舍**。行数、要点数和分区数不同，同一百分比对总高度的影响不同；一个空隙在视觉上被放大，也可能被另一个空隙变大后削弱层级感。这是视觉上的相互掩盖，不是高度上的加减抵消。

### 对比层：81种组合加权打分

同一 v23 文件还有一个算法对比层：每种间距取最小/中间/最大，组合出最多3⁴=81种；对各组合寻找能容纳的最大字号及目标余白，再按0.20字号、0.10间距、0.70余白的加权分选择结果。[v23 `algorithmProfileSet()`、`algorithmPenalty()`](../../prototypes/a4-spacing-algorithm-demo-v23.html)

它比共享进度更允许四种间距各自不同，81种组合也比只沿一条轨迹更有机会形成可见差别。但它仍有两个未解决点：权重把用户取舍藏进了分数；只试 min/mid/max 可能漏掉最接近0mm的版式。项目已有算法审查也提过联合搜索与权重，但当时建议软性纸底目标和舒适区间；用户现在明确选了靠近下边距线、目标0mm，所以该目标应以最新选择为准，不再把“是否接受30mm余白”当成悬而未决问题。[历史算法审查](../review/spacing-auto-layout-algorithms.md)、[原型版本记录](../../prototypes/README.md)

项目记录本身也指出，候选纸面只差约1.1mm时，肉眼很难分辨；纸底差约27mm后差别才明显。[原型版本记录：第二十至二十一版](../../prototypes/README.md) 因此“结果可见”不能只靠调整算法名称或显示不同的间距数字；演示应并排给出纸面、四个间距的实际值和剩余白纸毫米数。若两版余白只差不到1mm，视觉差异不明显是合理结果，应靠数字解释，不应伪装成很大的画面差异。

## 新候选：字号和空隙按比例一起缩放

这是用户刚提出的方向，记录为待验证方案，不是已确认规则：四边空白固定；先找出一套看起来舒服的比例；之后正文内容变多时，字号和空隙一起缩小，内容变少时一起放大，尽量用满可写区域。

可以把它想成一个统一的“整体大小”旋钮 `s`：

- 正文行高 = 正文字号 × 正文行距系数。
- 三栏行高 =（正文字号＋0.5pt）× 三栏行距系数。
- 要点间隔 = 正文字号 × 要点系数。
- 分区标题前间隔 = 正文字号 × 分区间隔系数。

四个系数就是各处空隙跟字号一起变化的“美观比例”。系数要从真实 A4 纸面效果中选，不能从 CSS 标准或算法论文里直接抄出。固定的18.5px 联系区距离等已冻结尺寸不进入这个旋钮。

总高度用大白话写就是：**纸上占用的高度 = 固定区块 + 正文每一行的高度加起来 + 三栏每一行的高度加起来 + 要点之间的空隙加起来 + 分区之间的空隙加起来。** 算法试不同的 `s`，在四边固定的可写区域里测量真实页面，选“没有超出、又最接近页底”的值。

需要注意，程序要数的是**字体和栏宽下真正显示出来的行数**，不是只数回车或要点数量。一条很长的要点会自动折成多行；字号变大时也可能多折出一行，使页面高度突然增加。中文/英文宽度、加粗、字体回退和三栏宽度都会影响换行，所以仍应使用真实页面测量。[W3C CSS Text](https://www.w3.org/TR/css-text-3/)、[W3C CSS Inline Layout](https://www.w3.org/TR/css-inline-3/#line-height-property)

GitHub 或个人网站是否存在，会影响联系区的内容和横向占位。联系区如果仍按已确认的两行固定高度处理，开关链接不会改变垂直行数；如果希望没有第二行内容时收起高度，那是另一条需要确认的规则，不能由自动排版悄悄决定。

**这种方式的好处：** 同一简历不会出现字号变小、某几种间距却反而变松的割裂感；内容量变化时版面保持同一套比例。**限制：** 只有一个整体大小值，不一定总能刚好贴到页底；换行会一整行一整行变化，字号/空隙也有上下限。贴不到底时应保留安全白边，不能破坏美观比例硬塞满。

它可以看作“页底先贴近”的搜索目标，加上“字号与四种间距按固定美观比例联动”的候选生成方式。下一轮纸面演示应专门验证：比起四种间距独立变化，这种比例联动是否更好看、在内容多少变化时是否仍稳定。

### 按这个想法，程序可以这样排

1. 先把字号设为10.50pt，按四个比例算出间距并试排。若全文放得下，就保持10.50pt和这套间距；内容少留下的白纸就留着，不为了贴底继续拉大间距。
2. 若10.50pt放不下，就把字号每次减0.01pt，四种间距按相同比例一起变化，每次都重新实际排版。选“能放下全文的最大字号”；通常这也会是最接近页底的一档。是否总是如此，需要在真实页面检查字号变大时高度不会反而变小。
3. 若8.50pt仍放不下，就保留全文并暂停PDF导出，按已确认规则提示用户。
4. 若字号在10.50pt时已经能放下，但底下空白很多，也不缩字、不拉大间距。这符合“内容不足就接受白纸”的新要求。

按候选范围的中间值，可以先算出一组**用于初次试排的数字**：正文行距1.375倍，三栏行距1.30倍；要点间距用“正文字号×0.158”，分区标题前间距用“正文字号×0.789”。在8.50pt时，后两项约为1.34pt和6.71pt；在10.50pt时约为1.66pt和8.29pt，落在目前候选的0.75–2.25pt和5–10pt范围内。这只是按候选范围取中点算出来的起步值，**没有通过纸面审美验证，也不是已确认字号配方**。

纯数字检查已把8.50–10.50pt的201档全部走过：这组起步值在每档都没有超出四种间距候选范围，且间距会随字号增大而增大。**这只证明算式和范围吻合，不证明纸面好看或内容能装下一页。** Computer Use 拒绝了本机 `file://` 演示页，且要求不通过本地服务器或其他浏览器绕过；真实页面高度、断行和视觉比例尚未目视核验。

若按每0.01pt试字号，共201档。内容量不会只记“打了几次回车”，还要用实际纸面看每个长要点折成多少行；每个字号档都要重新测量。用户提出的“字号到10.50pt仍有白纸就别硬铺满”也意味着这不是单纯追求0mm的算法：10.50pt能放下时，空白不再作为继续缩字或放大间距的理由。

## 三种真正不同的选择规则

下面三种不是同一算法换名字，而是“先满足什么”的规则不同。用户已确认想靠近页底；仍未确认的是：在几种结果都靠近页底时，字号和空隙节奏谁优先。

| 规则 | 程序先做什么 | 常见纸面结果 | 主要代价 |
|---|---|---|---|
| **字号先保大** | 空隙先取最窄，先找能放下全文的最大字号；再独立放大四种空隙，尽量靠近页底 | 字通常更大，空隙从紧凑开始逐项放开 | 取舍顺序固定；如果同样贴底的另一组“字稍小、间距更匀”更顺眼，程序不会优先选它 |
| **页底先贴近** | 同时试不同字号和四种空隙；先选没超页且纸底剩白最少的一组，再用“字号更大、间距更接近审过的样式”打破平局 | 最接近铺满；字号可能比字号先保大的结果小一点 | 需要大量候选；要定义平局规则。算法只能保证目标毫米数，不能自己知道哪种比例更美观 |
| **样式先好看** | 先由人确认几种间距样式（例如紧凑、均衡、舒展），程序只在样式内调字号并尽量贴底 | 每种简历节奏更一致，人工更容易比较 | 某份简历可能剩白多一些；需要先通过真实简历确认样式，而不是凭空命名 |

### 我推荐拿什么继续做对比

把**“比例联动 + 超出时逐档缩字号”作为当前主要候选**，因为它符合用户最新提出的字号与间距一起变化、内容少时保留白纸的原则；但美观比例仍需真实纸面校验，不能直接冻结。对纸底距离相近的结果，再比较“比例联动”和独立间距候选，确认统一比例是否更顺眼。

三条规则有时会选出同一页；只有在换行、字号步长或间距步长让结果出现差别时，才会明显看出它们各自的优先顺序。

搜索过程建议先生成少量有代表性的字号/间距组合，再用真实 A4 页面测量并逐步细化较好的区域；每轮明确报告“试过多少种、当前最佳剩白多少、是否只是在已试候选中最优”。如果同一页面多次运行必须稳定，候选顺序和平局规则也要固定。按0.01精度直接全量穷举约83亿组，成本不合适；局部细化又没有全局最优保证。开发前应以实测时间和候选覆盖率来定搜索策略。

## 五种技术路线比较

### 1. 共享进度：所有间距一起从窄到宽

**输入和输出：** 固定字号、四种间距的上下限、一个进度 `t`；输出一个字号和四个按同一百分比生成的间距值。**纸面效果：** 版面整体逐步变松，直到最接近页底或下一个进度会超出。**好处：** 规则短、实现直接、每次同一输入能得到同一版面。**失效点：** 一个类别需要多余白才看得出变化、另一个类别已显得太松时，算法不能偏向前者；不同长度的简历同样 `t` 会有完全不同的纸面影响。**业务适配：** 可保留为原型的简单基线，不建议仅凭“共同百分比”冻结正式算法。

### 2. 少量固定版式：紧凑、标准、舒展

每种版式是一组独立确定的四个间距值；在每组里按0.01pt找可容纳的最大字号，再选符合目标、余白最小的那组。它是项目历史审查里已有路线，尚未成为产品决定。[历史算法审查](../review/spacing-auto-layout-algorithms.md)

**输入和输出：** 少量经过真人纸面挑选的间距配方和正文；输出一个具名配方、字号和剩白数。**纸面效果：** 如果每个配方的四种间距确实有区别，用户能看出“紧凑/舒展”差异。**好处：** 最容易解释和复核；同稿重算稳定，调试不需要理解权重。**失效点：** 配方太少时可能错过0mm附近的结果；配方数很多又会变得难比较。它也无法从技术来源推导出“标准配方”应是什么。**业务适配：** 很适合作为结果展示和搜索的起点；若只选3个固定档，不能承诺总是最靠近0mm。

### 3. `space-between`：把所有多余空间平均摊到项目之间

浏览器对齐规则可把一个容器的剩余空间均匀分给各相邻项目；若把简历每个经历、要点或分区都当成对齐项目，就能直接让首尾贴住容器边缘。[W3C CSS Box Alignment](https://www.w3.org/TR/css-align-3/#distribution-values)

**输入和输出：** 固定字号与各内容块；输出固定的内容顺序和等分的新增间隔。**纸面效果：** 容易出现“顶部/底部贴齐、内容块中间被撑开”的铺满页。**好处：** 极直观，目标0mm容易实现。**失效点：** 它没有区分正文行距、同组要点和大分区层级；一个只有两块的简历与十几块的简历会按不同分母摊空间，视觉节奏也会随条目数变。它可能把求职简历变成被拉开的清单。**业务适配：** 可做极端对照纸面，不适合作为四种既有间距的正式分配规则。

### 4. 全局加权评分：所有目标合成一个“别扭分”

为每个候选布局打分：字号变小扣分、偏离舒适间距扣分、余白离目标太远扣分，选择分数最低的方案。Knuth–Plass 说明了“把候选和代价写清楚，再整体比较”的排版方法；但它的代价函数和权重是为段落断行设计的，不能直接挪作简历评分。[Knuth–Plass 原论文](https://doi.org/10.1002/spe.4380111102)

**输入和输出：** 候选范围、目标值、权重及实际排版高度；输出一个分数最低的候选和分项解释。**纸面效果：** 可以在字号与空隙间折中，也能强烈偏向铺满。**好处：** 表达力高，适合以后有明确且大量审美偏好时探索。**失效点：** 权重微调就可能换版；多个权重和单位归一化不容易讲给普通用户；纯粹追求最低剩白会主动把间距推到上限，即使看起来松散。**业务适配：** 现阶段不优先。已有 v23 对比层的20/10/70就是演示选择，不是研究来源证明的最佳比例，也不是产品规则。[v23 原型](../../prototypes/a4-spacing-algorithm-demo-v23.html)

### 5. 独立试排，按0mm目标逐级细化（实现手段，不是完整的取舍规则）

先把硬规则固定，再让字号和四种间距各自取候选值，而不是共用同一个进度。每次用真实页面测量；只保留没有越过279mm且联系方式通过检查的候选。对剩白 `R=279−H`，按0mm目标找最小的 `R≥0`。这只定义“贴近页底”，还没有决定贴得一样近时该选大字号还是更匀的间距；那是上面三种选择规则之一。`R` 不得小于0来自已确认的纸面边界，“平局规则”仍需确认。

建议的可解释步骤：

1. 先确定选择规则：字号先保大、页底先贴近、或样式先好看。规则不同，最终可能不同。
2. 生成候选字号与四种间距组合，用真实页面量高度；把超页、联系方式冲突的结果删掉。剩下的候选按所选规则排序。
3. 为了可用，不应逐一试约83亿种组合。可先用少量组合找方向，再细化较好的候选附近；但这样的结果只能说“在已试候选中最接近”。如果要保证步长范围内的绝对最优，需要证明能安全跳过未测试候选，或付出完整搜索成本。

**输入和输出：** 固定边界、字号/间距候选、完整简历和真实页面测量；输出被选中的字号、四种间距、剩白毫米数及“超页/可导出”状态。**好处：** 测量值直白可解释，不要求使用难懂的综合分。**失效点：** 独立搜索只负责找到候选，不能自己决定候选里哪种更好看；近似搜索也不能保证全局最优。**业务适配：** 作为三种选择规则共用的“试排工具”合适；最终选择规则要通过纸面效果确认。

这套搜索底座与已有81组合加权路线的差别不只是换名：候选可以复用，但**先筛掉超页结果，再明确比较剩白，不用0.20/0.10/0.70加权和；需要时在好候选附近细化**。对用户而言，理由从“得分高所以选它”变成“它完整放下全文，已试结果中剩白最少，为0.8mm”。

## 字号、换行、行距、段前距如何互相牵动

- **正文变大既让每行变高，也可能让文字变宽。** 字更宽时，固定栏宽能放的字符可能减少，额外换行使总高度跳增；英文、中文、粗体和字体回退的实际换行不能按平均字符宽度猜。[W3C CSS Text](https://www.w3.org/TR/css-text-3/)
- **行距数字不是固定毫米数。** CSS 的数字 `line-height` 乘以当前元素字号；正文字号变化时，同一个1.35倍对应的行框高度也会变。条目头字号又是正文＋0.5pt，所以三栏换行的行框也会随正文大小改变。[W3C CSS Inline Layout](https://www.w3.org/TR/css-inline-3/#line-height-property)、[`SPEC.md` L-09](../../SPEC.md)
- **段前距是局部增高，不是全页均匀增高。** 行距重复作用于每一行；要点间距作用于要点之间；分区前距作用于板块边界。因此相同“范围百分比”产生的总高度和视觉节奏取决于简历里有多少行、多少要点、多少分区。这是按 CSS 布局规则对 Resume 结构作出的推断，不是 W3C 推荐的简历审美。
- **固定的首段间隔要先扣除。** 联系区到首标题的18.5px在已确认规格中固定。测量实际页面时它自然属于总高度，但算法不能把它当作可调“段前距”来填空间。[`SPEC.md` L-17](../../SPEC.md)
- **字号搜索会有台阶。** 变量从10.50改为10.49pt可能毫无可见变化；也可能刚好让标题从两行变一行或反过来，使总高度突然跳一整行。CSS 规定可换行位置和行框高度，但没有规定“每0.01pt的总高度必然平滑变化”。所以近页底时应重测最终布局，不用线性估高。

## 小学生能看懂的算例

下面纯属解释算法的假数字，不是最终间距范围。把可写纸面想成一条100厘米高的盒子。最窄排法占91厘米，还差9厘米到盒子底边；四个间距如果放到最大，分别最多增加：正文行距4厘米、三栏换行2厘米、要点3厘米、分区7厘米。

共享进度会让四种间距一起动。假设 `t=0.56`，四处约增加2.24、1.12、1.68和3.92厘米，总共8.96厘米，底下剩0.04厘米；视觉上分区空隙也已经增加3.92厘米。独立搜索可以试“行距加4、三栏间距加2、要点加3、分区不动”，总共正好加9厘米，剩白也是0，但纸面节奏不同。

这不证明“分区不动”一定更好。它只说明：同样把页面铺到0余白，可以有不同的间距组合；算法和用户需要决定哪种组合更顺眼。最后一行若无法恰好贴到边界，就选仍在边界内、剩白最少的那组。

## 主要失效场景和处理

| 场景 | 算法应给的结果 | 原因 |
|---|---|---|
| 8.50pt、四种间距最窄仍超279mm | 保留全文，暂停PDF，提示删减 | 已确认的失败边界，[`SPEC.md` L-08](../../SPEC.md) |
| 联系方式固定两行却横向放不下 | 保留文字，暂停PDF并提示修改 | 缩小正文或挪垂直间距不能修复固定联系字号的横向溢出，[`SPEC.md` L-13](../../SPEC.md) |
| 最大间距仍离底线有空白 | 保留正向剩白，选当前范围内最接近的版式 | “尽量铺满”不授权超出四种间距上限或侵占9mm边距，[`SPEC.md` L-05、L-12](../../SPEC.md) |
| 某个正文改动触发多行换行 | 用最终渲染结果重新测高；接受版面出现一档变化 | 换行是按允许位置发生的离散事件，[W3C CSS Text](https://www.w3.org/TR/css-text-3/) |
| 相同内容重复排版选出不同候选 | 固定候选顺序、整数化字号和明确的平局规则；导出使用同一个最终测量结果 | 这是确定性设计建议；W3C 只规定几何测量接口，不决定产品如何打破平局。[W3C CSSOM View](https://www.w3.org/TR/cssom-view/#dom-element-getboundingclientrect) |

## 建议保留给用户看的解释

算法详情无需展示成分数或术语，纸面旁给一句具体原因即可，例如：“正文10.50pt，全文保留，四处间距在允许范围内；底下还剩0.8mm。”如果已经达到最大间距仍剩12mm，就直说“间距到上限了，纸上还剩12mm”。如果最小字号/间距仍超出2mm，就显示“正文完整保留，超出2mm，暂不能导出PDF”。这比抽象的“自动铺满完成”更能解释纸面结果。

正式导出需使用同一字体、栏宽、间距和最终测量结果，并核对PDF与编辑页一致；这是项目已确认的验收目标，不是上述算法或 W3C 规范自动保证的事实。[`SPEC.md` L-04、L-14](../../SPEC.md)

## 2026-10-15：按用户补充的真实数量范围做第一轮程序测试

用户补充：工作经历为1–3段、项目经历为1–3段；联系方式始终占两行，GitHub和个人网页在第二行，具体链接可选；其余主要变化来自正文要点的数量和长短。这让测试重点缩到9种经历数量组合和要点变化，不必把四个板块顺序或联系区行数当作随机变量。

用 [`check-linked-layout-model.mjs`](../../prototypes/check-linked-layout-model.mjs) 对字号8.50–10.50pt按0.01pt递减做了900个场景模拟。每个场景按工作/项目各1–3段、正文要点4–30条、四档固定内容高度，以及不同要点长度估算；联系区两行计入固定高度。结果中，379个场景在10.50pt可用，271个需要缩小字号，250个即使8.50pt仍会超出；650次“增加一条长要点”检查中，没有一次让选出的字号反而变大。候选系数在201个字号档内均落在四种候选范围中。

这是**公式和选择规则的估算测试，不是实际A4排版验收**。程序用约530pt的正文宽度、每个中文字符约占一个正文字号宽度、三栏每段暂按单行，以及160–220pt的固定内容高度区间。真实字体度量、三栏折行和浏览器行框尚未测量；因此这些数值只能说明算法方向在数量范围内没有明显自相矛盾，不能据此冻结系数。

本轮规则按最新用户意图理解为：从10.50pt起试；若放得下，就保留10.50pt和对应的固定比例间距，纸底仍有空白也不为贴线而继续改；若放不下，则按0.01pt逐档同时缩小字号和四类间距，取最大仍可容纳全文的一档；8.50pt仍放不下时保留全文并暂停导出。旧版v23的“先缩间距、再缩字号、再扩大间距”与81组合评分都不符合此规则，不能作为新规则的验证结果。

### 使用Mac字体宽度比较比例候选

第二轮用 CoreText 读取 v23 的虚构简历正文，并用本机的 PingFang SC、Times New Roman 测中文、英文和数字的折行；测试工作/项目分别1–3段，正文要点用原样稿及额外0、6、12、18条内容，共36个场景。垂直占高仍按 CSS 已知固定尺寸和候选行距公式计算，未运行浏览器或PDF版面，因此是比字符数估算更贴近Mac字体的模型，仍不是最终纸面验收。可用 [`compare-layout-coefficients.swift`](../../prototypes/compare-layout-coefficients.swift) 重跑。

| 候选 | 正文行距系数 | 三栏行距系数 | 要点间隔系数 | 标题前间隔系数 | 36种样本的结果 |
|---|---:|---:|---:|---:|---|
| 偏紧 | 1.30 | 1.20 | 0.110 | 0.600 | 8.50pt仍放不下19种；当前样稿9种经历组合都能放下 |
| **中间值** | **1.375** | **1.30** | **0.158** | **0.789** | **8.50pt仍放不下22种；工作和项目各1–3段的原样稿组合都能放下** |
| 偏舒展 | 1.40 | 1.32 | 0.174 | 0.842 | 8.50pt仍放不下23种；工作/项目各2段时，再加6条样例要点便放不下 |
| 舒展 | 1.45 | 1.35 | 0.200 | 0.900 | 8.50pt仍放不下25种；工作和项目各3段时原样稿都放不下 |

“放不下”的样本包含加到18条的额外要点，不代表真实简历出现的概率。更松的系数能把较满的纸面推近底线，但字号余量更少；偏紧较能保住字号，却可能留下更多底白。按“内容全保留、字号尽量大、同时希望接近底线”的综合目标，**建议先用中间值做下一版纸面候选，不冻结**：正文1.375倍；三栏1.30倍；要点间隔=正文字号×0.158；标题前间隔=正文字号×0.789。8.50pt时约为11.69pt、11.70pt、1.34pt、6.71pt；10.50pt时约为14.44pt、14.30pt、1.66pt、8.29pt。

对照样本：工作、项目各3段时，中间值模型选择8.57pt，纸底多留约5.5mm；偏舒展模型可把空白压到约1.1mm，但字号也接近下限，且对额外要点更容易超页。内容较少时，四组都停在10.50pt并留白，不为了贴底继续拉大间距。这符合用户最新说明。

系数仍要在真实编辑页上检查：CoreText 的断行和行高计算不完全等于浏览器；最终应把这些比例放进演示稿，用一份真实内容查看文字折行、层级和纸底误差后再冻结。

补测使用[`compare-layout-coefficients.swift`](../../prototypes/compare-layout-coefficients.swift)：字号每加0.01pt，估算占高在36种场景×多组系数下共36,180次都没有反向下降；工作和项目各1–3段、每种再增加0–6条模拟要点，共189次字号选择检查通过。工作/项目各2段时，中间值可在原样稿上选9.51pt、余白约0.1mm；加6条样例要点后选8.57pt、余白约1.1mm；加到12条额外要点后，8.50pt仍放不下。对照之下，60%舒展组在原样稿3段工作+3个项目时能贴近纸底，但工作和项目各2段、再加6条时已经超出。基于容量余量与靠底效果的平衡，中间值暂列首选；不把极限贴底作为唯一目标。
